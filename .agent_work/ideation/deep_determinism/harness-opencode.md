# Harness: OpenCode

OpenCode is the primary harness for ContextSmith. This companion describes how to optimize the orchestrator skill for OpenCode.

## Agent Launch

OpenCode runs agents via the CLI:

```bash
opencode run --agent <profile> --model <provider/model> --file NEXT_PROMPT.md --format json
```

**Verified CLI flags (2026-06-12):**

| Flag | Purpose |
|------|---------|
| `--agent <name>` | Agent profile to use (defined in `.opencode/agents/*.md`) |
| `--model <provider/model>` | Model to use (e.g., `ollama/qwen3:6b`) |
| `--file <path>` / `-f` | Attach file to the message |
| `--prompt <text>` | Prompt text (alternative to --file) |
| `--format json` | Output raw JSON events instead of formatted text |
| `--session <id>` | Continue an existing session |
| `--continue` | Continue the last session |

**Not available:**
- `--max-steps` — use agent config `steps` field instead
- `--prompt-file` — use `--file` instead
- `--timeout` — use harness adapter timeout instead

## Agent Config Format

OpenCode agents are defined in `.opencode/agents/*.md` with YAML frontmatter:

```yaml
---
description: Audits artifacts for reliability
mode: subagent
steps: 10
permission:
  edit: deny
  bash:
    "*": deny
    "python scripts/validate_skills.py": allow
  webfetch: deny
  external_directory: deny
---
```

### Permission Model

| Permission | Values | Description |
|---|---|---|
| `edit` | `allow`, `deny` | Can modify files |
| `bash` | `allow`, `deny`, or pattern rules | Can run shell commands |
| `read` | `allow`, `deny`, or pattern rules | Can read files |
| `webfetch` | `allow`, `deny` | Can fetch URLs |
| `external_directory` | `allow`, `deny`, or pattern rules | Can access outside project |
| `question` | `allow`, `deny` | Can ask user questions |
| `plan_enter` | `allow`, `deny` | Can enter planning mode |
| `plan_exit` | `allow`, `deny` | Can exit planning mode |

### Agent Modes

| Mode | Description |
|---|---|
| `primary` | Main agent, full access |
| `subagent` | Delegated agent, limited access |

## Step Limiting

Since `--max-steps` doesn't exist, step limiting is done via:

1. **Agent config `steps` field** — hard limit on tool calls per invocation
2. **Prompt instructions** — "stop after completing the task" or "use at most N tool calls"
3. **Timeout enforcement** — harness adapter kills subprocess after timeout_s

## Result Protocol

### Primary: RESULT.json

The agent writes `RESULT.json` to the task-state directory before exiting:

```json
{
  "status": "pass",
  "reason": "All artifacts produced and validated",
  "artifacts": ["ARTIFACTS.md", "PHASE_LOG.md"],
  "issues": [],
  "next_action": "done"
}
```

### Fallback: Artifact Presence

If RESULT.json is missing, the harness infers status from:
- All expected artifacts exist → pass
- Some artifacts missing → fail
- No artifacts → fail

### Fallback: Exit Code

- Exit code 0 → agent completed normally (task success determined by artifacts)
- Non-zero → agent crashed

## Structured Questioning

OpenCode supports the `question` tool (AskUserQuestion) for structured multiple-choice questions. Use it for:
- Confirmation before execution
- Parameter selection
- Plan approval

The tool accepts questions with options and returns the selected label.

## Installation

To set up ContextSmith for OpenCode:

```bash
# Install the orchestrator skill
cp -r skills/contextsmith-orchestrator/ ~/.agents/skills/

# Create agent configs
mkdir -p .opencode/agents/
# (agent configs are generated by contextsmith init --harness opencode)
```
